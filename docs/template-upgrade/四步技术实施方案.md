# 独立站首批五套新模板建设与模板库接入方案

日期：2026-09-26。状态：第1步调研中；尚未执行新模板开发、注册或数据迁移。

用户已明确：按腾讯表格前五项建设五个新的独立站模板，加入现有模板库供后台选择。现有模板的布局和客户选择均保持不动；每家公司从模板库中选择一个模板，不是让同一家公司同时使用五个。实施分四步。

## 目标与本次调查边界

目标是在现有模板库中增加五个独立的新模板，每个模板使用当前公司自己的内容与后台维护入口。现有模板视觉与使用关系不改。为保证新模板可用，可以新增隔离的模板渲染、数据绑定与页面组件；不把修复旧模板作为本次目标，也不让新模板的改动改变旧模板输出。

继续使用 `platform-v1` 的 Next.js、Payload、PostgreSQL 和多租户体系；不扩展上级旧 JSON 后台，不重新建五套内容数据库，不另做五套后台。

## 整体技术路线

```text
现有运营后台（选公司 / 首页 / 内容 / 分类 / 关于 / FAQ / 联系 / 导航 / 站点）
                     ↓
既有Payload集合 + 少量模板展示设置
                     ↓
公司权限、语言、发布状态、媒体归属校验
                     ↓
统一站点数据模型 SiteViewModel
                     ↓
模板定义（key + version + 模块顺序 + 展示变体 + 设计参数）
                     ↓
共享业务组件 + 五套布局组合
                     ↓
首页 / 列表 / 详情 / 固定页 / 手机端 / 询盘
```

“共享”的是产品查询、翻译、分类、询盘和权限；“不同”的是导航结构、区块顺序、图文比例、卡片、内页侧栏、字体间距和色彩。五套不能只是同一页面换主色。

以下严格分四步。每步输出可查看的页面或文档、可核对的记录和问题清单，完成后标记“待用户验收”。本次方案批准不自动等于批准生产迁移或替换正在使用的客户站。

## 第1步：冻结五套设计、后台映射和现状基线

### 用户会拿到什么

五张模板说明卡、每套完整页面清单、前后台字段对应表、现有问题优先级、后续文件和迁移清单。先明确每个按钮、图片、标题在后台哪里改。

### 1.1 补齐参考拆解

每套逐页检查：首页；产品列表/分类/详情；新闻列表/详情；案例列表/详情；关于；FAQ；联系；页眉页脚。博客由本平台现有博客适配，不宣称五个参考站已有相同博客实现。

记录每页：区块顺序、桌面宽度、图片比例、每行数量、文字长度、侧栏、联系入口、空数据行为、手机收折、点击目标。补录1440、768、390 CSS像素视口，并用DOM内的实际视口宽度确认尺寸生效。截图等待轮播和入场动画稳定，避免把加载状态当缺陷。

输出 `REFERENCE_AUDIT.md`、`references/`，每条发现有URL、日期、截图或DOM证据及“已观察/待验证”标识。

### 1.2 现有站点基线

只读统计每公司的产品、分类、新闻、案例、博客、FAQ、媒体、询盘、页面、导航数量；记录四语代表内容、选用模板、版本、启用语言、关键图片/PDF引用及真实访问路径。记录当前缺陷，不自动删除或覆盖看起来像测试的数据。

实施前确认可用后台会话或账号。数据库基线查询不改权限、不运行seed。执行结构变更前准备数据库备份、媒体引用清单、恢复方法，在独立测试库验证恢复。

输出 `BASELINE.md`及本地必要的脱敏记录摘要。不要把询盘全文、密码、cookie写进公开证据。

### 1.4 五套页面规格

建议稳定标识分别为 `interior-575-v1`、`power-705-v1`、`autoparts-571-v1`、`machinery-710-v1`、`solar-test-655-v1`。这些是拟新增标识，尚未写入数据库。

完整模板至少覆盖12类页面：首页、产品列表、产品详情、新闻列表/详情、案例列表/详情、博客列表/详情、关于、FAQ、联系。分类状态属于列表，404和空状态属于公共底座。每套都要有内页设计，不能仅首页不同。

### 本步验收

能逐块指出“这个内容去后台哪里改”；五套区别能从布局图看出来；确定缺失字段和旧字段保留规则；基线可复核；不存在把未读页面写成已验收的情况。仅完成方案分析不等于已经完成本实施步骤的全部证据。

## 第2步：为五个新模板建立隔离的渲染与数据适配底座

### 用户会看到什么

后台原有模板仍按原样运行；新增能力只供五个新模板使用。五套新模板统一读取当前公司内容、语言、分类、产品图库/规格书和询盘；新实现与旧模板注册分开，先在预览环境验证。

### 2.1 数据读取和页面模型

新增拟定目录：

```text
src/platform/new-templates/
  types.ts                 模板、模块、数据模型类型
  registry.ts              key+version注册表
  validate.ts              运行时白名单与兼容性检查
  resolve.ts               模板版本与设置合并
  legacy.ts                仅供新模板使用的既有字段兼容适配，不接管旧模板
  loadSiteViewModel.ts      按公司、语言、页面读取业务数据
  links.ts                 站内、外链、锚点、邮件和电话解析
  service.ts               应用、回退、版本冲突与审计
  definitions/             五套新模板定义
  components/              共享业务组件及展示变体
```

`SiteViewModel`包含site、locale、navigation、branding、home、products、categories、news、cases、posts、faq、contact及pageMeta；按页面需要加载，不每页查询全部内容。模板组件不能自己绕过租户约束查库。

公共读取始终有tenant过滤；含草稿的集合默认只取published。后台Local API用户操作显式传 `user` 和 `overrideAccess:false`。前台受控服务使用系统读取时必须显式限定租户、发布状态、语言和字段投影，不能直接暴露数据库结果。

首页查询明确 `tenant + slug=home + published`。缺home时使用规范化的站点首页配置，不取最近更新的任意页面。

### 2.2 模板定义及优先级

拟定类型示意，实施时以生成的Payload类型为准：

```ts
type TemplateDefinition = {
  key: string
  version: string
  schemaVersion: number
  reference: { code: string; url: string }
  supportedPageTypes: PageType[]
  capabilities: Capability[]
  defaults: {
    tokens: DesignTokens
    headerVariant: HeaderVariant
    footerVariant: FooterVariant
    homeSections: SectionDefinition[]
    pageVariants: Partial<Record<PageType, string>>
  }
}

type SectionDefinition = {
  id: string
  type: SectionType
  variant: string
  source: 'homepage' | 'products' | 'cases' | 'news' | 'posts' | 'about'
  enabled: boolean
  limit?: number
}
```

白名单固定模块及变体，不允许数据库保存可执行JS、任意React组件名或不受限CSS。内容正文继续存在原集合，模板配置只保存展示选择。

优先级：模板默认布局 → 当前站点明确保存的展示覆盖 → 现有内容开关/数量/发布状态。`false`和空值必须区分，“关闭”不能被模板默认值重新打开。缺数据直接隐藏对应区块，后台解释缺少什么；模板切换不能自动填充演示内容。

站点已有品牌色保留；未配置时使用模板默认色。用户选择“采用模板配色”时，预览明确列出变化。优先沿用现有九模块编辑器；调整顺序/变体在首页管理内提供，页脚仍作为全站设置，不能被拖到首页中间。

新注册表只管理五个新增key。旧四个key继续由当前既有渲染路径处理，不搬迁、不重构，也不改变默认/未知key的旧行为；模板库读取时同时展示原有记录和新增记录，但新模板的适配逻辑不覆盖旧模板。

### 2.3 必修功能的具体实现

**分类：** 服务端读取category、page；用当前公司分类slug解析ID，父类含受控两级子类，products按category过滤；无效分类显示未找到而非默默返回全部。分页默认12项，稳定排序 `sortOrder,id`；移动端分类抽屉和桌面侧栏共用查询状态。清除筛选返回全部。

**Banner：** desktop/mobile使用响应式图片；保留旧URL兼容，同时支持当前公司媒体ID和焦点；标题空不影响整张图/CTA可点击；站内链接统一解析站点和语言；旧链接若包含本站其他语言前缀，解析为当前语言相同业务目标，外部站点链接不强行转换。导航横幅使用独立InnerPageHero组件。轮播提供键盘、暂停、减少动画偏好支持。

**导航：** 新模板的 `resolveSiteLink` 区分 `/products`、当前公司完整内部路径、`#anchor`、HTTPS外链、mailto、tel；拒绝javascript等不允许协议。不把外链拼进 `/s/...`。新模板手机支持二级折叠，由五套新布局共用该组件。FAQ是否自动补入需与现有菜单行为明确：建议由已保存菜单决定，不在每次渲染强制加回用户删除的菜单。

**产品详情：** gallery优先、历史externalImages回退；提供缩略图切换与图片说明；datasheet存在才显示下载；参数按localeCode读取并保留旧规格字段兼容。详情“询价此产品”进入站内RFQ并携带productID，服务端校验产品属于本公司且公开，再写入leads.product；邮件链接可作为附加联系方式。

**询盘：** 首批使用姓名、公司、邮箱、电话、需求五项；可选国家/产品沿用现有字段，不把kVA固定带入所有模板。历史capacity数据保留，不改写。姓名、邮箱、需求沿用Leads既有强制规则，在后台明确标为固定必填；公司/电话可配置，前后端共用规则。现有冲突设置在界面提示并按统一规则展示，不静默抹掉旧配置。若未来要允许三项为空，另作业务规则和迁移评审。

表单标签、校验和反馈有en/zh/ru/id字典；网络失败catch/finally恢复可提交状态、保留输入，成功才清空；无效邮箱即使在兼容路径也必须正确校验。保留蜜罐与频率限制；部署多进程时频率计数使用共享存储。可选短时幂等键防止网络重试重复生成lead，不把“点击发送成功”当成数据库保存成功。

**多语言：** UI用字典；客户正文用原localized字段；翻译完成度用fallback关闭查询。Banner逐项补`contentByLocale`结构，保留原title/description回退且后台标注未翻译；旧中文内容不自动复制成四语。模板不决定站点开启哪些语言。停用语种不出现于导航、站点地图和hreflang。

**SEO：** 每个页面构造自身canonical及同内容的语言对应链接；列表不能继承首页canonical。产品、案例、新闻、博客使用各自元信息；Product JSON-LD不虚构价格、评分或库存。FAQ JSON-LD与可见内容一致。模板切换不改产品slug和原URL。

### 2.4 拟增字段与迁移边界

| 位置 | 拟增内容 | 必要性与兼容 |
| --- | --- | --- |
| templates | referenceCode、referenceURL、schemaVersion；行业选项按需补家居/汽配 | 追踪参考来源及兼容版本；旧记录可为空；不改旧key |
| tenants | templateSettings（JSON展示设置）、templateRevision（整数，初始0） | 存模块顺序/变体/受限主题覆盖；旧站没有该字段时走legacy解析 |
| 首页配置 | sectionLabels（localized JSON，受Schema验证） | 少量模块标题/说明可按语言编辑；不重复存产品正文 |
| banners现有JSON | 稳定id、可选媒体引用/焦点、contentByLocale | 增量兼容，不删除旧URL；每个引用校验租户 |
| 新集合site-template-changes | tenant、before/after展示快照、revision、actor、operation、idempotencyKey、createdAt | 只记录模板配置变更，为原子应用和可控回退提供依据 |

样式/模块默认定义保存在版本化代码中，不把同一manifest同时维护在多张表。模板封面建议使用项目静态资源，避免平台共享模板关联某个客户的私有media。tenant内容仍使用当前公司的media。

迁移先出SQL/数据映射和dry-run差异；测试库运行新增字段、旧记录兼容及恢复；不批量回填参考演示素材。既有模板版本字段需绑定真实保留的定义版本，版本号不能只是显示文字。数据库结构变更在实际执行前按项目规则确认具体清单。

### 2.5 文件范围与验证

新增独立模板运行时/数据适配文件（实施前按仓库现有目录核对），包含新的模板注册表、数据适配层和共享组件。旧模板key、文件、页面分支和输出不做重构。若确实需要修改旧模板共用文件，应先把新逻辑隔离到新的入口/组件，并证明旧模板前后页面没有变化。

本步只验证五套新模板的数据契约：分类确实筛选、Banner链接遵循本站/语言、图库和规格书使用当前公司数据、询盘进入正确公司且产品关系正确、跨公司访问被拒绝。P01—P14作为本机现状风险记录；只为新模板增加必要的适配，不顺手改写旧模板行为。

## 第4步：完善模板库选择、预览应用回退，并完成全链路验收

### 用户会看到什么

在后台模板库看到原有模板及新增五张模板卡。每家公司可预览多种模板，但同一时刻选择一个模板生效；应用新模板前看到外观变化，原有业务内容保持不变，之后仍可切回原先模板。

### 4.1 后台交互

保留现有侧栏。站点管理中的模板区域从下拉扩展为模板卡片：封面、中文名、参考编号、适用布局、版本、状态、支持页面、预览和应用。首页管理显示当前模板支持的顺序/布局；不支持的设置解释原因，不让用户保存无效果的选项。

预览显示当前公司、语言、模板和版本，支持首页/产品/案例/新闻/固定页切换以及实际设备尺寸。缺少图片或内容给出后台提示，公开页面使用合理空状态。不能只拿一张静态截图当模板预览。

应用前展示差异：模板、模块排列、卡片/页眉页脚、配色覆盖；明确哪些站点展示设置被保留。公司内容、产品、媒体、询盘、导航、slug不作为模板应用的写入对象。

### 4.2 接口契约

拟新增同公司上下文接口：

| 接口 | 输入 | 成功结果 | 关键约束 |
| --- | --- | --- | --- |
| GET `/api/workspace/[company]/templates` | 分页/行业过滤 | 支持当前渲染器的published模板，当前版本 | 用户有公司权限；平台未注册实现的模板不可应用 |
| POST `.../templates/preview` | templateId、version、locale、pageType、settingsPatch | 有效期10分钟的预览会话/入口、差异摘要 | 不写tenant配置；预览内容与权限绑定 |
| POST `.../templates/apply` | templateId、version、expectedRevision、idempotencyKey、settingsPatch | 新revision、应用记录ID、前台入口 | 完整校验后原子更新，仅写模板展示状态 |
| POST `.../templates/rollback` | changeId、expectedRevision、idempotencyKey | 恢复后的新revision | 同公司历史；旧渲染版本仍可运行；不回退业务内容 |

401未登录、403无公司/角色权限、404记录不存在、409版本冲突/已过期差异、422配置不合法或能力不兼容。失败中文提示保留用户选择，不显示假成功。

旧 `/api/apply-template`委托统一service；`site-settings`不再独立绕过预检改模板。SiteManager更换模板走新接口，普通域名/语言保存仍走原设置入口。兼容旧客户端时也必须进入相同服务逻辑。

### 4.3 预览与应用实现

预览可放在 `/workspace/[company]/template-preview/...` 独立路由，复用同一renderSite组件；会话服务器端保存或受签名保护，绑定用户、公司、模板版本、有效期及允许的页面。不能用 `?template=任意key` 向公众开放草稿或他人数据。

默认使用当前已发布内容做预览；若支持草稿须单独校验编辑权限。所有预览页及响应设noindex、no-store，不进入sitemap；内部导航保留预览上下文，外链不携带预览凭据。token、密钥不写进日志和证据。

应用流程：鉴权→检查当前公司→验证模板版本存在且published→验证设置白名单及媒体归属→对比expectedRevision→在数据库事务内锁定/条件更新站点、写before/after快照和审计→提交事务→刷新本站各语言/相关路由缓存→返回真实结果。

并发保护不能只在事务前读一次revision，必须在更新时原子比较或锁行。重复幂等键返回同一结果；同一键不同请求体返回冲突。事务内多次Payload操作共用req/transaction上下文；实际API以本地Payload 3.88安装源码和官方对应文档为准。

当前前台使用force-dynamic，但仍需梳理已有revalidate逻辑；缓存键和失效范围含tenant、locale、templateVersion、内容版本。缓存刷新失败需明确“配置已保存，刷新待重试”，避免用户重复应用。

### 4.4 回退与发布边界

`site-template-changes`快照只包含selectedTemplate、templateVersion、templateSettings、revision及本次确实改动的展示配置。产品、正文、FAQ、媒体、询盘不在回退范围。若之后人工改过展示配置，回退前显示冲突差异，不能用旧快照无声覆盖后续编辑。

保留仍被客户站/可回退记录引用的模板版本；不能删除旧组件后声称还能回退。回退产生新记录，审计不可由普通编辑修改。模板回退与代码部署回退是两件事；数据库优先采用增量兼容方式，不靠删除新字段做紧急回退。

后台“应用”只表示选择的模板外观生效，不等于域名已绑定、站点已发布或生产部署成功。生产迁移和真实客户站切换按项目既有发布清单另行执行；先在隔离测试环境验证。

### 4.5 验收矩阵与明确证据
