# 部署、发布与回退说明

本文件描述记录要求，不是对生产环境执行操作的授权。生产发布、迁移、重启和回退必须由负责人逐次批准。不要把本地 `docker-compose.yml` 当作生产配置。

## 当前生产服务对应

2026-10-15 核查时记录的正式服务版本：Web `v1-rc-20261005-1-cloud`；独立翻译 Worker `v1-rc-20261004-7-cloud`；PostgreSQL `17.11-bookworm`；Caddy `2.11.2-alpine`。运行平台为阿里云香港 ECS，管理域 `admin.o669.com`。镜像 ID 和源代码对照记录见 [release 基线](./RELEASES/production-baseline-2026-10.md)。

生产 Compose、Caddyfile、环境变量、镜像拉取凭据、SSH 信息和数据库目录不在公开仓库。本地旧 `deploy/` 内容未被认定为当前生产配置，不可直接使用。

## 推荐的版本管理流程

1. 以 `main` 为集成分支，功能从最新 `main` 建立 `codex/<topic>` 或同等短期分支。
2. 一个可审阅的提交只表达一个明确变更，提交说明包含影响模块和必要迁移提示；不提交客户数据、生成缓存、运行日志或密钥。
3. 合并前检查 diff、凭据扫描、类型/静态检查和隔离验证。涉及数据库或权限的修改需单独评审与恢复方案。
4. 由负责人批准后创建不可移动的源码发布标签。建议源码使用 SemVer（例如 `v1.1.0`），发布注释记录 commit、迁移号、Web 镜像构建信息和 Worker 构建信息。现有 `v1.0.0` 标签必须保持原位。
5. 从精确的 Git commit 分别构建 Web 和 Worker 镜像，给 OCI image 写入 Git commit、构建流水线、依赖锁文件摘要和发布时间元数据。分别记录镜像 registry digest（不要只记录可变 tag 或本机 image ID）。
6. 先在隔离环境验证，再由负责人批准生产部署。部署前创建数据库和媒体备份，确认备份可读；记录迁移状态、当前镜像摘要和健康检查结果。
7. 部署后核对 Web 与 Worker 版本、健康路由、管理登录、租户访问边界、内容读取、询盘落库和翻译任务消费；不得用生产客户数据做破坏性测试。

当前生产 Web/Worker 发布标签使用 `v1-rc-YYYYMMDD-N-cloud` 形式；在建立新流程前，先保留并准确记录旧标签，不要重打或挪动既有标签。RC 标签本身不表示正式产品完成验收。

## 回退原则

- 先区分应用故障、数据库迁移和客户媒体问题。应用镜像回退不能自动回退数据库 schema。
- 如果迁移向前兼容，先回退 Web/Worker 镜像至已登记的上一组摘要，再按负责人指令处理迁移。
- 若 schema 已不兼容旧版，暂停应用回退；需要在已验证备份副本演练恢复，再制定停机窗口和数据合并方案。
- 回退后重新核对 Web/Worker 版本、数据库迁移记录、管理登录、租户隔离和队列状态。
- 不允许以 `docker compose down -v`、删除数据库 volume、seed 或覆盖客户媒体的方式处理生产故障。
