# 第5步：文章生成、编辑与引用

日期：2026-10-17。授权：第4步交付后用户要求“继续”，本轮执行8步方案的第5步。继续遵守多客户隔离、素材只用素材组、保留原客户数据和不做知识库的要求。

2026-10-18修订见[实际流程修复记录](./FLOW-REPAIR-20261018.md)，当前生成状态规则以该记录及下文修订为准。以下最初交付范围及当时测试结论保留作历史记录。

最初交付状态：3100代码、本地增量表和独立生成工作进程已接入，**待用户验收**。没有打开页面、制作展示截图或进行浏览器验收；没有真实AI调用、真实客户文章写入或对外发布。第6—8步没有提前开始。

## 1. 操作入口与状态

在已保存的创作任务配置下增加“生成记录”：

- 输入本次生成数量，最多10篇，并且不能超过任务配置数量、实际可处理且未重复的问题数。
- 未保存修改、缺少来源、工作进程未就绪时不能从页面直接开始生成。首次进入读取真实记录，不填充演示文章。
- 开始生成只登记后台任务，返回排队状态；生成不依赖浏览器持续打开。存在排队/运行记录时每5秒读取进度，不会用轮询请求触发模型。
- 每条记录显示问题、任务修订、排队/生成中/已生成草稿/失败/结果未知、说明及调用次数；有文章才出现查看/编辑链接。
- 失败可显式重试原记录；未知结果需确认前次可能产生用量。已经生成文章的记录不能用重试覆盖文章。

侧栏增加“创作记录”：

- `/workspace/[company]/geo/articles`：本客户文章列表、标题搜索、20条分页、语言/方向和状态。
- `?taskID=...`：只看本任务文章，查询仍附带当前客户限制。
- `/workspace/[company]/geo/articles/[id]`：文章详情、富文本编辑、来源依据、人工核查和历史修订。

“可发布”是完成本步核查的内部状态，不代表已对外发文。文章发布、发布计划和发布记录入口仍属于后续步骤。

## 2. 固定版本与生成前复查

排队时在服务端读取当前客户的已保存任务，核对期望任务版本及来源状态。每条生成记录固定关联：客户、任务ID/修订、问题UUID、原文/译文、品牌/别名、优化词版本、素材组版本、用图数量、方向、长度及来源快照。

问题与文章通过稳定ID及修订关联，不使用数组位置。改任务名称、编辑文章或恢复历史正文不会回写旧任务快照。

准备阶段：

1. 从任务快照选择与该题对应的最多3个独立来源页；根网址不能充当引用。核心词问题至少有一个相关细分词来源，细分词题需要对应词来源。
2. 从任务素材组的有序快照确定不同的图片，数量严格等于每篇用图数；没有其他素材配置方式。
3. 工作进程重新读取提交人的角色、客户归属及到期时间，确认客户仍存在；来源读取完后、模型调用前再次核对权限。失权时停止且不调用模型。
4. 核对优化词和素材组仍是对应版本，分组未归档。图片ID、原URL、格式、大小和组成员关系必须仍属于该客户。
5. 用第3步的受限来源发现服务重新读取本题使用的官网/Blog范围；只接受原任务来源URL中仍可达、可索引、正文足够、主题匹配的页面。冻结本次实际读取的标题、摘录、匹配词和检查时间，不更新原任务或来源索引。
6. 来源复查继续遵守robots、DNS固定、内网/保留地址拒绝、重定向和域名/路径边界、响应大小及请求预算。不执行页面脚本、不携带用户Cookie。原页面改址到快照外的新URL时保守拒绝，需要更新任务来源。
7. 来源、图片或方向依据不足则记录明确原因并停止，不先调用模型再伪造“有依据”。

来源发现仍有第3步的12请求、每根最多5个候选等预算限制；复杂站点可能无法在一次请求内复查完，需要完善站点或更新任务，不能将受限检查失败当成页面不存在的绝对结论。本轮来源响应来自受控fixture，没有抓取真实客户网站。

## 3. 11种方向如何执行

AI匹配会根据问题确定为技术解读、场景化问题解答或产品介绍，记录实际方向；不随机抽方向，也不宣称额外调用了一个“方向选择模型”。

产品介绍、技术解读、场景化问题解答、行业问题解答、行业百科、知识科普使用对应问题及匹配来源。其余方向增加必要条件：

| 方向 | 本步的必要条件 |
|---|---|
| 企业榜单 | 至少3个匹配来源，并出现明确排名/比较方法线索；不足直接拦截 |
| 体验分享 | 来源中有实施、运行、使用或项目记录线索；不能把产品示意图当客户体验 |
| 企业推荐 | 来源中能识别当前公司主体，内容仍需引用能力依据 |
| 新闻报道 | 来源中有事件/公告线索及明确日期，不允许模型补造日期 |

这些规则是资料门槛，不是完整事实审计。关键词命中不能证明榜单客观、案例真实或新闻仍具有时效性；自动校验通过的结果进入可发布，校验失败的结果进入待编辑；这并不证明全部事实语义正确。来源、排名方法、事件和公司事实仍可人工核对。

## 4. 正文服务与依据约束

模型请求只在服务端发送，复用现有DeepSeek配置；浏览器不接触密钥。调用前登记本次attempt，记录模型和发起时间。只传当前题、当前客户品牌、语言/方向/长度以及本题来源摘录，不传其他客户数据。

模型返回结构化JSON：标题、摘要、章节、段落、每段的sourceID及原始摘录中的连续引文、待核查事项。它不直接输出可执行HTML，也不选择任意图片或URL。

服务端处理：

- 检查2—12个章节，每章1—6段，字段和长度有上限。
- 每段sourceID必须来自本次提供的来源集合，依据引文必须能在对应摘录中找到；缺少或伪造依据时，该次生成失败，不保存成成功文章。
- 逐段转义文本，再由服务端插入该来源的链接、任务素材组图片，随后执行统一GEO白名单HTML规范化与内容检查。
- 不凭空生成规格、认证、测试结果、客户案例、奖项、排名、价格、公司能力或体验。提示词明确要求只使用已有依据，图片只作配图，不证明客户项目。
- 记录模型返回的事实不确定性事项。2026-10-18修正：校验通过的正文保存为**可发布**，不通过则待编辑，避免自动计划永远取不到新生成文章。
- HTTP超时90秒，最多8192输出tokens，响应最多512KiB，没有模型自动重试。
- 响应中可识别的usage在正文结构校验前保存；格式失败也保留已有用量。缺失usage为null，不能记成零消耗。

“引文存在”只证明提供了一个可定位的文本片段，不证明该段落的全部推论都由引文支持。模型语义真实性、所述企业能力和结论仍需人工判断；本轮没有以mock结果冒充真实模型质量验证。

## 5. 后台队列、去重和中断

数据流程：

`用户明确提交 → generation_requests → 每题generation_jobs → 领取租约 → 权限/来源/素材复查 → 登记attempt → 模型 → 草稿与初始修订原子保存`

- 同一请求UUID和相同任务/版本/数量重放只返回原请求，不重复排队；复用编号提交不同内容返回冲突。
- 去重键覆盖品牌配置、问题内容/意图、目标语言、方向、长度、素材组版本/图片数量及来源内容。仅改任务名称不会得到一批重复文章。已经排队、失败或成功的相同问题从新建候选中排除；失败请重试原记录。
- 循环模式仍是用户明确发起的有限批次，每题每批最多一篇；没有后台无限发文。
- 数据库限制全局最多2条正在运行、同客户最多1条；本地启动1个工作进程，逐篇处理。不同客户可由多个工作进程并行，但不能绕过单客户限制。
- 租约240秒，每20秒续期；失去执行权的旧进程不能写usage、创建文章或覆盖结果。
- 准备阶段未登记模型调用就中断的记录，可以重新排队；已经登记调用的记录中断后为**结果未知**，绝不自动重发。登记之后、发出HTTP之前崩溃也保守记未知。
- 明确重试时使用原job、创建新的attempt，原attempt、usage和错误保留。已经有文章的job不能重试覆盖文章；文章ID与job绑定且有唯一约束。
- 默认每客户每UTC日最多10次正文调用，`GEO_ARTICLE_DAILY_LIMIT`允许1—100。成功、失败、未知attempt都计数。限额是GEO正文调用次数保护，不是金额预算，与原翻译账本分开。
- 文章与初始修订、job成功和attempt成功在同一事务提交；失败不会留下半篇文章。超时或提交结果不明时先读取记录，不盲目新增任务。

接口：`GET/POST /api/workspace/[company]/geo/generation`。普通读取、进度轮询和取回文章不触发模型调用。

## 6. 编辑、引用检查与可发布状态

编辑器沿用现有工作台的contentEditable、选区保存、格式命令及安全粘贴模式，支持标题/摘要、二三级标题、粗斜体、下划线、列表、取消链接、插入引用及任务组内图片。没有新建图库、上传系统或单图素材策略。

GEO使用专门的规范化HTML白名单：所有文本转义，标签受限，原属性不整体复制；不保留事件、script、iframe、SVG、任意样式、外部图片或未知链接。链接只能来自该文章来源集合；图片只能来自任务选定图片集合。服务器保存时再次处理，不依赖浏览器粘贴过滤。文章读取时过滤不再属于当前客户或URL已变的媒体。

每次保存检查：

- 正文至少保留一个带可见文字的独立页面引用，空链接不能算有效引用。
- 不同图片数量与任务配置一致，图片仍属于该客户素材组；重复同图不会算多张。
- 短篇中文150—1000字符，其余语言80—1000词；长篇中文500—2000字符，其余语言300—2000词。计数及结果出现在待处理原因中。
- 正文书写系统与目标语言相容；存在来源摘录没有的数字时阻止可发布。
- 方向资料门槛仍成立。

书写系统检查能发现明显中文/拉丁/阿拉伯/西里尔文本不符，**不能可靠区分英语、西班牙语、德语和印尼语**；数字存在于来源中也不代表单位和语义正确。真实语言质量、数字含义和事实关系都需人工核查，不能说已经完全自动验证。

2026-10-18界面改为直接“保存”，不增加核查勾选或强制核查说明；保存前仍实际复查来源与素材，通过校验则可发布。内部草稿保存能力保留。任何结构问题仍保存成待编辑并列出原因；来源复查失败会返回错误，保留输入。服务端不接受客户端直接指定status、context或snapshot。

修改已可发布的文章并保存草稿会重新成为待编辑。删引用、图片失效、未核对的数字等不能靠只勾选确认绕过。第6步真正发布前还须重新验证当前修订与来源，不把本次可发布状态当成永不过期的保证。

文章修改采用版本比较，同版本并发修改只有一个成功；失败不会覆盖用户输入。每次成功修改产生新修订，并保留核查人、说明、时间。历史正文可填回当前编辑器，保存后成为新修订，不回退或覆盖原修订，也不回写创作任务。

接口：`GET /geo/articles`、`GET/PATCH /geo/articles/[id]`；历史读取`?version=N`，全部位于当前公司workspace API下并带tenant限制。

只在`platform_geo`新增5张表：

| 表 | 内容 |

| generation_jobs | 问题、去重键、任务/执行快照、状态、租约和当前调用 |
