## 一、已确认的产品边界

1. 这是一个管理多个客户的统一运营后台。GEO是“独立站”旁边的模块，复用已有登录、公司选择、权限和工作台外框。
2. 每次进入GEO，都有明确的当前客户。优化词、素材组、问题、文章、发布账号、任务和检测结果必须属于该客户。
3. 品牌以客户实际配置为准，不把原型中的“澄川电气”自动写入任何真实客户。
4. 每组配置为一个品牌词、一个核心词、十个不重复细分词；一个客户可有多组不同核心词。
5. 配置页保留：品牌词、比对标识、核心词、细分词、网址链接、Blog链接。添加弹窗只填品牌词和核心词，确认后补全详情。
6. **不展示“发文引用子链接”配置表，也不要求客户为十个词逐个填写URL。** 发文时自动附带当前客户配置的官网及Blog链接；不要求抓取页面内容。
7. GEO发文必须带上该客户已配置的官网和Blog链接。有明确独立子链接配置时使用对应链接；没有时使用所配置地址，不编造URL。链接仅用于跳转，不用于生成正文依据。
8. 创作先做搜索词模式；素材配置只使用素材组。暂不做企业知识库，也不顺带扩展其他营销模块。
9. 界面沿用现有NovaSite蓝白风格。减少重复Logo、装饰图标、长说明和没有依据的成功状态。
10. 不模拟真实搜索命中、真实平台发布成功或模型训练收录。

## 二、GEO的目标与衡量方式

GEO不是单纯让模型知道公司名称。要建立“用户问什么 → 是否出现该公司 → 是否推荐该公司 → 引用了哪个具体页面 → 是否带来访问与询盘”的关系。

业务链：

`当前客户 → 品牌/别名 → 核心词与细分词 → 问题池 → 来源页 → 素材与创作 → 发布 → 跨平台观测 → 按缺口修订`

以下状态必须分开：

| 现象 | 意义 | 不能推断的事情 |
| --- | --- | --- |
| 自己文章已保存 | 平台内部有内容 | 不代表已对外发布 |
| 平台发布成功 | 目标返回了可核查的内容记录 | 不代表搜索引擎已收录 |
| 回答出现公司名称 | 品牌被文字提及 | 不代表正面推荐或引用 |
| 回答附带官网/Blog具体页面 | 页面被该回答引用 | 不代表稳定排名或永久收录 |
| 某个问题多次出现品牌 | 该条件下有可观察覆盖 | 不代表所有平台、语言、地区相同 |

先用非品牌问题检验发现能力，例如“如何选择低压成套配电柜供应商？”。品牌自查问题单独统计。记录平台、模型、联网条件、语言、地区和时间，保持问题集可重复。推荐语境要单独识别；负面回答也可能提到品牌。

## 三、多客户隔离与权限

### 3.1 复用现有身份与公司上下文

- 页面入口：`/workspace/[company]/geo/...`。
- API入口：`/api/workspace/[company]/geo/...`。
- 页面复用公司工作台布局；服务端从当前登录用户可访问的公司列表解析URL中的company。
- 复用现有`payload-tenant`选择机制，但cookie仅负责选择，不作为后台授权依据。
- 所有业务读取与保存再次核查URL公司、登录用户权限、目标记录tenant归属。
- 切换客户时保留GEO模块，返回新客户优化词列表，关闭旧弹窗、取消旧请求、清空旧勾选和未暂存内容；有未保存修改先提醒。
- 旧标签页的后台请求始终使用其URL公司，不因全局cookie变化写入另一个客户。

### 3.2 角色策略

沿用现有角色：`super-admin`、`site-admin`、`editor`、`sales`。第1步GEO入口与页面开放给前三种内容运营角色；sales不开放GEO编辑入口。

后续API按动作收紧：编辑可维护优化词、素材和文章；账号授权、发布开关、删除与自动发布控制由site-admin/super-admin执行。权限由服务端落实，禁用按钮只辅助界面提示。若要更细的客户级角色，单独扩展，不虚称当前已有。

Payload Local API以用户身份调用时必须传`user`及`overrideAccess: false`。系统Worker也要有明确tenant过滤与运行主体；不可把管理员权限当作允许跨客户关联的理由。媒体、分类、账号及来源页关系均检查双方tenant一致。

### 3.3 数据与执行隔离

- 业务数据统一带tenant关系（GEO内部表沿用项目独立schema模式）；查找、分页、计数、导出和批量操作都包含tenant限制。
- 唯一性按tenant范围定义，例如`tenant + normalizedBrand + normalizedCore`。
- 草稿、请求缓存、队列幂等键、任务锁和存储路径都带tenant标识。
- 客户数据不保存在共享全局localStorage，不共用发布令牌或AI密钥。
- 异步请求使用AbortController/请求版本，切换后忽略旧结果。
- 修改已有客户内容、数据库迁移和正式发布必须按项目现有变更流程另行执行。

## 六、比对标识与内部引用规则

### 6.1 比对标识

含义：帮助系统识别AI回答中的本公司名称。填写公司全称、英文名、品牌别名，以斜杠/换行分隔；品牌词自动参与。

处理规则：全半角、大小写归一化；中文处理空格和标点变化；英文保留单词边界，避免缩写命中其他单词。行业词、竞品名不作为自己的别名。自动模糊推测只能进入待人工复核，不能直接记成功。匹配证据保存命中名称、上下文及配置版本。

别名只影响观察结果的识别，不向外部模型添加品牌指令，也不能改变其搜索结果。

### 6.2 不展示子链接表后的实现

1. 客户只填官网和Blog范围；可复用当前客户已有正式站点配置。
2. 优先从本平台该客户已发布产品、新闻、案例、博客中读取真实URL；如有外部Blog，再在配置域与授权范围内读取sitemap或抓取页面。
3. 校验协议、域名/路径归属、重定向、状态码、canonical、抓取权限、页面主题与发布状态。允许的Blog独立域名通过配置明确登记，不能无限扩大抓取域。
4. 抓取实施SSRF防护：拒绝内网、回环、链路本地、云元数据地址；每次DNS解析及重定向重新核查；设置超时、体积、深度与频率限制。
5. 创作输入是核心词、细分词、搜索问题、语言和方向；知识库接入后优先使用该客户知识。官网/Blog文本不进入正文提示词。
6. 没有企业知识库时按关键词生成通用行业内容，不编造特定企业的认证、案例、排名或能力。
7. 保存、生成、编辑和发布均不依赖网页可达性或网页内容引用。以前的“待补充来源”任务可按关键词生成，但配置版本与素材归属仍须有效。
8. 发布适配器在写入新闻/Blog正文时补上客户配置的官网和Blog链接；已有对应链接不重复追加，不能替换成其他客户域名。
9. HTML安全、素材归属、客户隔离、语言和长度仍校验。保存成功只显示“保存成功”，token保留内部记录，不在页面展示。

**技术：** 对问题保留细分词、意图和原文/译文ID对应；供应商、厂家、批发/代理、产品行业、Top比较等模板是意图，不生成未经核实的排名。问题去重基于规范化内容，翻译不能靠文本位置丢失映射。供应商调用在服务端执行，记录usage、超时、失败及重试；不把模板结果冒充模型真实返回。

**任务：** 保存配置与素材快照；素材组、每篇图片数量、方向（沿用原型确认的11种）、长度、去重/循环方式；生成数量不超过实际可处理问题数。任务与AI调用均带tenant、版本、幂等键与可核查状态。

**核查：** 中文与英文问题可追溯；失败不覆盖编辑输入；不同客户任务隔离；不因重复点击多扣额度；源问题修改后明确旧文章关联版本。

### 第5步：文章生成、编辑与引用

**当前进度：** 持久化生成队列、后台进程、调用/中断记录、素材归属复查、结构化正文服务、富文本编辑和文章修订已接入3100。最初安装时表为空；本次已在公司“1”生成三篇真实AI文章，并保存手写文章。最新执行结果见流程修复记录；历史安装指纹与检查仍保留。详见[第5步实施与边界](./STEP-05.md)。待用户验收；后续进度见第6步记录。

**交付：** 后台生成任务、进度、创作记录、文章查看/编辑、图片及发文链接；按问题回答采购需求，不只反复宣传公司。

**技术：** 冻结问题/品牌/来源/素材版本；生成后校验正文、语言、长度范围、来源URL及图片归属。禁止伪造规格、认证、检测数据、排名、客户案例或把示意素材当客户项目。HTML消毒和安全链接统一处理；富文本保留现有编辑器能力，优先复用项目组件。

**状态：** 排队/生成中/待编辑/可发布/失败。生成与保存均执行图片、语言和长度校验；全部通过则可发布，失败则待编辑并说明原因。不增加强制核查勾选或说明。文章修订不回写任务快照。

**核查：** 正文回答对应问题；发文附带同客户配置链接；删去正文中的链接不阻止生成或保存；生成中可恢复/重试且不重复造文章；仅对受控测试客户调用真实AI。

### 第6步：手动发布与真实发布记录

**当前进度：** 已接入当前客户默认语言的本站新闻/Blog发布，支持选择创作记录或直接写文章；无额外发布确认页面。服务端仍检查目标、修订与幂等，保留单次指定时间、真实CMS回读、同事务结果账本、取消/明确重试和持久化工作进程。最初安装时两张表为空，安装前后行指纹检查保留。本次已在测试公司“1”实际生成5条成功发布记录，并打开真实页面核对；历史独立空白库验证与本次业务验证分开记录。详见[第6步实施与边界](./STEP-06.md)。待用户验收。

**交付：** 选择文章/人工编辑、关联优化词、选择账号或站点/Blog分类、立即或指定时间发布；记录可核查目标结果。

**技术：** 先接现有本平台站点/Blog，明确发布目标集合；外部平台逐个通过适配器接入，不默认复刻页面就代表已授权。适配器能力包含发布、查询结果和可用的失败恢复；令牌只存服务端。记录文章版本、来源、外部ID/URL与错误分类。

**幂等：** `tenant + articleRevision + target + publishIntent`，重试前先判断目标是否已创建；不能因为超时盲目再次发文。手动确认与实际发布执行是两个状态，不允许点击确认直接伪造成功。

**核查：** 目标站点/分类属于本客户；草稿和发布状态区别；外部成功URL可核查；权限/配额/授权过期有明确失败提示；不覆盖旧内容。真实对外测试需明确授权客户、目标和内容。

### 第7步：发布计划与自动调度

**当前进度：** 发布计划页面、只读逐篇目标/时间预览、客户时区调度、人工审核/跳过、管理员自动确认、执行事件及第6步队列衔接已接入。本地测试公司已运行计划。按客户时区的小时段、日间隔执行；无库存文章时自动把所选任务的新问题入生成队列，合格正文继续本轮发布。生成失败记原因，未知结果不自动重试；等待生成期间重启进程不会重复创建AI请求。独立schema-only PostgreSQL/Payload检查覆盖跨客户来源、并发审核/跳过、自动生成衔接及重复派发。详见[第7步实施与边界](./STEP-07.md)。页面仍待负责人验收。

**交付：** 日期周期、时区、按小时选择发布时间、间隔天数、人工审核/自动确认、任务/多文章来源、一篇多发/多篇多发、启停与执行记录。计划每个间隔周期只执行一次，默认每天在一个选定小时段执行；旧版按分钟保存的计划仍按原配置运行。

**规则：** 一篇多发为每篇向全部所选目标发布；多篇多发按明确顺序/轮转分配给目标，不能隐藏分配策略。计划预览每篇的目标和时间，避免误发。人工审核必须先同意才能进入执行。

**技术：** 服务端持久化队列与Worker；UTC存储、按计划时区解释，考虑夏令时；任务领取锁、去重、限流、退避、失败上限、取消和重启恢复。修改/暂停计划不影响已完成事实，未执行项按版本取消后重排。租户配额与额度不足明确阻塞。

**核查：** 独立库已检查数据库锁下的单次派发、时区和夏令时、周期终止、租户来源隔离、人工审核/跳过竞争、自动计划只入现有队列。暂停只停止后续计划派发，不撤销已经进入第6步队列的任务。Worker实际客户计划尚未启用；真实目标效果仍待负责人验收。

### 第8步：搜索词追踪、闭环报告与交付

**交付：** 词/问题→平台→公司名称命中→推荐语境→实际引用页→时间趋势；支持查看原始答案、来源URL和历史配置。无数据是“未检测”，超时是“检测失败”，均不能当作未提及或0%覆盖。

**采样：** 固定问题集版本、平台/模型、联网模式、语言/地区、执行时间和批次；品牌自查与非品牌发现分开；保留多次采样，显示波动。优先使用官方API/报告及允许的查询方式，不绕过平台限制。手动录入应标明来源，不冒充自动验证。

**统计：** 提及率、有效引用率、问题覆盖率分别使用明确的有效样本分母；无有效样本显示“—”。引擎内部grounding query与用户完整问题分开记录。一次命中不等于稳定排名，发布前后差异不自动声明因果效果。

**闭环：** 找到未覆盖的问题、缺少来源的细分词、失效/内容薄弱页面，再回到站内内容与文章任务。后续可关联GA4的来源访问与询盘，但不把所有询盘归因GEO。

**交付：** 双客户读写隔离、四语言兼容、现有独立站回归、来源安全、队列恢复、幂等、权限和受控真实调用证据。修复问题后由负责人验收；代码完成不代表生产部署。正式发布和迁移仍按现有上线流程单独执行。

## 八、统一接口与状态约定

- 成功读写只返回本客户必要字段；错误使用`code/message/fieldErrors/requestId`，不能把provider令牌或完整堆栈返回界面。
- 生成/抓取/发布/观测均使用operation ID供状态查询；页面刷新可以恢复进度。
- 创建类请求有幂等键；编辑有version/updatedAt冲突检测；删除有关联先说明影响，必要时归档。
- 外部URL既保存原始形式，也保存规范化身份；不同语种路径不得错误去重。
- 任务完成数、文章数量、发布成功数和有效引用数来自真实记录，禁止用前端按钮直接加成功数。
- 第1步的内存类型仅为界面模型，不直接作为第2步数据库schema；GEO内部表采用共享TypeScript领域类型、SQL约束与服务端校验；涉及Payload原集合时仍复用其生成类型与权限。
