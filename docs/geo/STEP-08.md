# 第8步：搜索词追踪与闭环报告

完成日期：2026-10-17。项目：`platform-v1`，本地工作台端口3100。

## 页面与工作流

新增客户工作区页面 `/workspace/[company]/geo/visibility` 与 API `/api/workspace/[company]/geo/visibility`。页面从当前客户已保存的GEO优化词配置进入，配置选择覆盖分页结果，不固定绑定某一家客户。

问题集分为“品牌自查”和“非品牌发现”，语言使用站点支持的语言代码。用户可逐题维护，也可根据已配置的品牌词、核心词和10个细分词生成11条可编辑建议问题。问题集每次更改都会递增版本；提交采样时固定该版本和当前优化词版本。移除的问题不再进入当前统计，历史答案和原始问题仍保留。

当前采样方式是人工采样：用户在目标平台按固定问题实际搜索，粘贴完整答案，并填写平台/模型、联网状态、语言/地区、可见的引擎内部检索词和答案引用URL。系统不自动调用AI平台，也不从文章生成结果伪造观测。引擎内部检索词与用户问题分栏保存；检索词只会成为一个待编辑的问题草稿，不会自动写入问题集。

每个有效原始答案都会按采样时的品牌词与比对标识进行确定性匹配。命中后由录入者标记正向推荐、中性提及、负向评价或语境不明，并保留原始答案供复核。系统不根据品牌词推断推荐语境。已完成但未命中记作“答案未提及”；没有采样记录显示“未检测”；超时/失败保存原因为“检测失败”。后两种状态不会被算成未提及。

## 统计口径

- 有效回答样本只包含已保存原始答案的“已提及公司”和“答案未提及”记录；失败样本不计入分母。
- 公司提及率 = 命中品牌词或比对标识的有效回答数 / 有效回答数。
- 有效引用率 = 至少引用一个已核验来源页的有效回答数 / 有效回答数。
- 问题覆盖率 = 当前问题集中至少有一条有效回答的问题数 / 当前问题总数。
- 没有有效回答时，提及率、引用率和覆盖率都显示“—”。品牌自查与非品牌发现分开计算；问题行另显示各平台拆分。趋势按北京时间、日期和平台聚合最近100条记录。
- 只有URL匹配当前租户、当前优化词版本下状态为“可访问”的来源页，才计入有效引用。URL规范化保留路径大小写，不抓取用户提交的外部URL；不在已检查来源清单中的链接仍会保存并显示“未核验”。

单次命中不代表稳定排名；采样前后差异也不能单独证明由某次发文导致。报告只描述当前保存的样本和来源证据。

## 内容闭环

页面按每个细分词展示来源页覆盖情况、扫描状态和可访问页面。没有对应独立页面或来源不可用时，提示先在当前客户网站补充页面，再从优化词详情重查来源；来源通过后可回到现有文章创作流程。正文少于300字符会出现明确标注的启发式长度提醒，仅用于人工检查，不代表内容质量判定。页面不自动修改网站内容。

有效回答中记录的内部检索词会作为候选线索回填到问题编辑框，用户需编辑并确认后才能保存。这样保留了“用户完整问题”和“引擎内部检索词”之间的区别，也避免把检索词误当成真实用户提问。

## 数据与多客户隔离

新增`20261017_070000_geo_visibility`迁移及三张表：`tracking_sets`、`observation_batches`、`observations`。问题集按`tenant_id + optimization_id`唯一保存；观测批次与答案记录均含租户键，使用复合外键绑定当前租户优化词、对应优化词修订和观测批次。历史批次冻结问题集及品牌配置快照。

读写先通过当前登录用户可访问的公司范围，再把服务端解析出的客户ID用于每个查询。请求体不能指定客户ID。问题集写入使用版本比较；观测创建使用客户端幂等编号和内容哈希，网络重试返回原记录，不重复增加分母。采样事务锁定当前配置，串行化来源刷新和优化词更新，使来源核验依据与保存的配置快照一致。删除问题不会删除历史答案。
