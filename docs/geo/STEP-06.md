# 第6步：手动发布与真实发布记录

日期：2026-10-17。状态：**3100本地接入完成，待用户验收**。本轮由用户“继续”授权；用户明确选择先接客户站点默认语言。没有浏览器验收、截图展示、真实客户试发、生产部署或第7步周期计划工作。

## 1. 交付范围

GEO侧栏开放“文章发布”和“发布记录”。文章编辑器中，当前修订已经核查为可发布且没有未保存修改时，可以进入发布页。

发布流程：

`选择当前客户已核查文章 → 选择本站新闻/Blog及客户分类 → 选择时区和单次发布时间 → 预览 → 明确确认 → 等待后台执行 → 查看真实记录`

- 文章与分类均可搜索、分页；其他语言/待编辑文章不能在发布页提交。
- 页面显示当前客户、文章修订、品牌/核心词、目标分类、默认语言、预计地址、执行时间和摘要；正文通过原文章编辑入口查看及修改。
- 手动发布支持直接填写标题和正文，不强制选择素材组或图片；如需配图，只能选择当前客户素材组中的图片。正文必须含有一个与所选关键词匹配、带可见文字的独立子链接，前端先校验，服务端保存时再次校验。
- 发布时间可按选定时区指定并转换UTC保存；留空时按参考站默认当前时间，计划进入立即执行队列。指定时间允许1分钟后至90天内。实际执行仍受工作进程状态及队列影响。
- 预览不创建请求、不写CMS。确认登记后显示等待发布，不直接显示成功。
- 切换客户时复用现有workspace保护与组件重挂载；请求中止、旧响应忽略、忙碌/未确认预览离开提醒沿用工作台机制。
- 失败保留输入。记录刷新能恢复进度，排队/运行时每5秒读取一次，不因轮询重复发文。

本阶段只支持本平台新闻与Blog，不显示虚假的外部平台账号或授权状态。发布计划、周期、多目标分配属于第7步。素材配置仍只有素材组，没有知识库。

## 2. 默认语言与多客户权限

用户已确认：本步只创建客户站点默认语言的内容，其他语言通过现有翻译管理补全。CMS的已发布状态由多语言共用，所以该限制同时在界面、预览及工作进程执行前检查；不把一种非默认语言的正文直接当作完整多语文章发布。

HTTP接口复用登录、当前客户Cookie与可访问公司校验，允许现有内容运营角色super-admin/site-admin/editor手动发文；这与当前CMS内容编辑发布权限一致。账号授权、发布开关和第7步自动发布权限另行收紧。本轮没有新建账号授权或修改原角色模型。

- 请求不能指定tenant。记录、文章、历史事件、计数和取消/重试都由服务端当前客户条件限定。
- 分类明确检查tenant归属；管理员也不能把甲客户的GEO文章关联到乙客户分类。
- Payload读写传入真实操作人、`overrideAccess:false`、明确tenant及locale。后台重新检查原提交人的最新角色、客户关联与有效期，不依赖旧浏览器登录状态。
- Worker在来源复查前后各检查一次授权；丢失权限会失败，不写CMS。
- 已停用、尚未上线、默认语言已变、目标分类已删或改动、域名改变等均阻止按旧预览发文。修正目标需要取消未完成请求并重新确认。

## 3. 预览签名与重复保护

预览有效期5分钟，签名绑定文章正文/标题/摘要/人工核查说明、修订、目标、执行时间、客户及操作人。签名密钥只在服务端，使用现有PAYLOAD_SECRET。确认必须带`confirmed:true`、签名、有效期及请求UUID。

文章状态、版本及目标在确认时重新读取；修改正文、撤销可发布、变更目标或过期后必须重新预览。浏览器不能通过提交`state:published`或目标ID伪造成功。

重复保护包含两层：

1. 同一请求UUID及相同内容重放返回原记录；同编号换内容返回冲突。
2. 同客户、同文章修订、同栏目集合、同语言只能有一条未取消记录。换分类或执行时间不能绕过已存在记录重复发文。取消尚未执行或已明确失败的请求后，才允许重新确认。

已发布记录不能取消或重试覆盖。文章新修订若明确再发布，会创建一个新的站点内容，不自动覆盖之前版本。

## 4. 后台执行与真实成功依据

队列状态：等待发布、发布处理中、站点已发布、发布失败、结果待核对、已取消。事件追加保留确认、开始、失败、未知、重试、取消和成功的时间及操作人。

工作进程先实际复查独立引用页、优化词/素材组版本、图片归属/类型/大小，并按第5步规则重新验证正文、图片数量、语言、长度和依据。来源响应注入仅用于独立测试；生产执行会使用真实来源服务。

真正写入前在同一个Postgres事务中完成：

1. 锁定当前客户发布记录，核对有效租约；检查文章最新修订、可发布状态及冻结正文。
2. 再读站点、默认语言及分类；锁定组与媒体，核对图片仍是当前客户、组版本未变、URL未变、允许图片类型且不超过500KiB。
3. 检查确定的目标slug是否已有内容。有冲突直接停止，不接管、更新或覆盖旧内容。
4. 通过原Payload集合创建一条新的已发布新闻或Blog，传入客户、分类、默认语言、Lexical正文及素材封面。
5. 在同事务回读实际内容编号、标题、客户、slug及已发布状态。
6. 写实际CMS编号、目标地址、成功状态及事件，随后统一提交。

CMS创建、原CMS版本钩子和发布结果账本共用同一个Payload事务；结果事件失败时，新增内容和版本一并回滚。没有通过原始SQL绕过CMS内容校验或替换现有集合。

成功依据是CMS实际创建结果和回读；目标URL由现有站点域名/路径规则及实际slug生成。**本步没有对公网URL发HTTP访问验证，也没有证明搜索收录或模型推荐。** 界面明确区分这些状态。

站点路由现有`force-dynamic`读取内容；独立Worker对Blog传`disableRevalidate`避免脱离Next请求时调用缓存失效函数，其他CMS钩子仍执行。没有改动站点模板或原内容。

## 5. 正文格式

GEO安全HTML转为当前CMS支持的Lexical节点，保留标题、段落、粗斜体、下划线、列表、换行、引用链接和素材组图片。链接只能是文章允许来源，图片只能是该文章组选定媒体；不保留事件脚本或任意样式。

当前目标编辑器未启用表格，因此遇到表格明确拦截，提示先改为段落；不悄悄丢掉表格内容。标签不完整、标题/链接中嵌套不支持的块结构也会提示整理。

独立测试库使用真实CMS创建与回读，并用现有富文本转换工具确认图片和来源链接可转为HTML；这不代替浏览器页面验收或真实素材文件访问检查。

## 6. 中断、重试与取消

- 数据库约束每客户最多1条运行任务；全局最多2条，本地1个独立进程逐条执行。
- 租约240秒，每20秒续期。旧执行者失去租约后不能创建内容或覆盖结果。
- 执行中断、租约到期或提交确认丢失保守标记结果待核对，不自动重发。
- 未知结果需人工核对原记录与站点内容，明确确认后才能重试；确定目标slug冲突仍会拦截，不能盲目复制一篇。
- 明确失败可在原记录重试，历史事件仍保留；重试会重新检查权限、文章、来源、素材和目标。
- 排队或明确失败可取消；运行中、未知或已成功不可用取消按钮伪装撤回。撤回已发布站点内容仍通过原CMS管理，不属于本步。

当前站内发布没有供应商调用/扣费，也未发现既有客户发布篇数配额模型；本步没有宣称已接入套餐额度系统。外部平台限流、授权过期、配额及生产进程管理在对应适配器/后续步骤落实。

## 7. 接口、增量表与本地运行

接口均在`/api/workspace/[company]/geo/publish`下：

| 操作 | 接口 |
|---|---|
| 本客户发布记录 | GET根路径，分页20条 |
| 本客户分类/默认语言/状态 | GET根路径，view=options，collection=news或posts，支持q/page |
| 详情与追加事件 | GET /[id] |
| 预览/确认/取消/重试 | POST根路径，action=preview/confirm/cancel/retry |

只新增`platform_geo.publish_intents`、`platform_geo.publish_events`两表，联合外键关联当前客户文章修订。未修改Payload客户集合，未执行全量schema push或其他待执行迁移。已登记正式迁移；down明确拒绝删账本，应用回退时保留事实记录。

本地安装前做项目外0600私有pg_dump备份，随后在事务内增量建表。已启动专用发布Worker，未重启3100及既有生成、翻译、通知进程。

```sh
node --env-file=.env --import tsx scripts/geo-publish-worker-local.mts status
node --env-file=.env --import tsx scripts/geo-publish-worker-local.mts start
node --env-file=.env --import tsx scripts/geo-publish-worker-local.mts stop
```

Worker采用production数据库适配模式，禁止开发schema push；仅执行用户明确确认的发布请求。PID/日志/心跳位于已忽略的`.codex-runtime`，35秒内心跳作为本地就绪提示。没有配置生产守护进程、跨主机心跳或高可用部署。
