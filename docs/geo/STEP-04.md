# 第4步：搜索问题、扩词翻译与创作任务

日期：2026-10-17。授权依据：用户在第2/3步之后要求“继续”；沿用已确认的本地GEO增量接入、多客户隔离、素材配置只用素材组、保留已有客户数据的边界。

状态：代码与3100本地存储已接入，待用户验收。没有打开页面、截图展示或浏览器验收。2026-10-17按用户授权，对`runGeoQuestionAI`直接执行了2次真实DeepSeek请求：配电柜采购问题扩词1次、中文问题翻译为英文1次。共返回20条问题和1条译文，供应商报告用量合计856 tokens。请求未经过工作区HTTP接口/租户用量账本，没有保存优化词、任务或AI操作记录。此项只验证供应商连通和响应解析，**不代表接口鉴权、幂等/额度记账、真实问题池效果或译文质量已经验收**。

## 1. 当前客户的文章创作入口

GEO侧栏开放“文章创作”，继续使用3100工作台、当前公司和既有角色权限，不另建后台外壳。

- `/workspace/[company]/geo/creation`：当前客户任务列表、按任务名称搜索、20条分页、来源状态、配置入口。
- `/workspace/[company]/geo/creation/new`：新建任务。
- `/workspace/[company]/geo/creation/[id]`：已保存任务的稳定配置地址。

配置分成四段：

1. **任务信息**：名称、文章语言。语言选项复用项目现有语言定义，不改变客户已开启的站点语言。
2. **文章关键词**：选择本客户已保存的品牌/核心词配置，显示品牌及比对标识；勾选核心词/细分词，选择搜索意图，建立并编辑搜索问题。
3. **素材组**：只能选择本客户未归档素材组及每篇用图数量。此页没有指定单图、随机图库或知识库配置。
4. **创作方式**：11种方向、长度、去重/循环模式、本批篇数；检查来源与保存任务。

比对标识仍是品牌/公司称呼的别名，不是竞争对手名单，也不等于AI推荐证据。第8步将分别判断“出现公司名称、推荐该公司、引用该公司独立页面”。搜索问题用于覆盖买家的真实采购问题，不把每个问题都变成品牌宣传句。

11种方向沿用已经核对的原型：AI匹配、企业榜单、产品介绍、技术解读、场景化问题解答、行业问题解答、行业百科、体验分享、企业推荐、新闻报道、知识科普。本步保存方向，不声称已实现这些方向的正文生成；榜单/体验/新闻所需事实及资料约束在第5步执行。

## 2. 问题与原文/译文关系

- 当前任务最多100题。每题保存稳定UUID、所属核心/细分词、搜索意图、原始问题、译文、译文对应原文、译文语言。
- 搜索意图包括通用、供应商/服务商、厂家、批发/代理、产品与行业、Top比较。Top比较用于提出需要核查的比较问题，不自动生成企业排名。
- “添加基础问题”使用明确的本地意图模板；“AI扩词”才调用供应商。模板内容不会被标为模型真实返回。
- 支持手工逐题修改、移除、按行批量添加。批量手工问题归属第一个勾选的搜索词；基础问题分别归属各自词。规范化NFKC、空白及大小写后去重，不合并只是意义相近但内容不同的问题。
- 扩词返回最多20题，服务端核对所属词、文本长度及结构，规范化去重；合并到现有问题池，不清空原输入。
- 翻译请求/结果按问题UUID映射，返回顺序改变也不能串题；缺少/额外ID会整体拒绝本次结果。
- 翻译按文字量分批，单次最多30题、原文合计1800字符。用户点击后处理当前一批，不静默连续付费调用。已成功题保留，后续点击处理剩余题。
- 原文修改会清空该题旧译文对应关系；目标语言不符、原文已经变化、缺少译文时，不能保存为外语创作任务。可人工填写和修改译文，保存对应原文与语言。
- 翻译复用现有数字/型号/链接保护逻辑。输出编号、受保护内容或新增数字校验不通过时，不返回部分译文覆盖输入。此校验不能保证模型在所有语义上都正确，仍需人工核对。
- 本步问题池嵌入任务配置及任务修订JSON，不另建Payload问题集合。后续文章用“客户 + 任务修订 + 问题UUID”关联，保持旧文章来源可追溯，不以数组位置关联。

## 3. 服务端调用、幂等与恢复

接口：`GET/POST /api/workspace/[company]/geo/ai`。POST只支持扩词与问题翻译；没有正文生成或发布功能。

供应商使用现有服务端`DEEPSEEK_API_KEY`、`DEEPSEEK_MODEL`配置及固定官方API地址。密钥不返回浏览器、不保存到GEO表；请求只带本次配置的品牌/词/问题，不读取其他客户上下文。配置缺失时明确返回不可用，不以模板替代成功响应。本次只检查环境配置是否存在，没有输出密钥。

每次调用先在GEO调用表登记并提交，再发出HTTP请求：

1. 服务端从登录/当前公司解析tenant及操作人；拒绝客户端指定tenant、跨站写入、越权角色与旧公司页面。
2. 核对优化词ID、版本及问题/词归属。计算规范结构的输入摘要；请求UUID相同但内容不同返回冲突。
3. 数据库事务锁限制同客户同时只有1个正在处理的调用。同一请求的并发提交只有1次能领取，其他请求取回已登记状态/结果。
4. 相同请求UUID即使失败或中断也不再次领取；成功重放和GET取回均不发起模型调用。客户端也有提交锁与按钮禁用。
5. 默认每客户每UTC自然日最多20次，服务端`GEO_AI_DAILY_LIMIT`可设1—200；成功、失败及未知请求均占用次数。该限制是GEO调用次数保护，不等于供应商金额预算，也不改动现有翻译用量账本。
6. 单次HTTP超时45秒，输出最多4096 tokens，响应上限256KiB。供应商错误、格式错误、映射错误均有可核查错误码；不记录供应商原始敏感错误内容。
7. 本阶段**不自动重试付费调用**。正常失败后可从处理记录明确重新调用；结果未确认时，重新调用前提示前次可能已经产生用量。
8. 状态为处理中、成功、失败、结果未知。超过2分钟仍未完成的记录，取回时显示未知，下次领取时固化未知状态；不回收原请求再次执行。处理记录显示当前配置最近10次结果，可显式应用成功结果。
9. 结果取回再核对配置版本、语言、问题UUID及原文。旧译文不会覆盖已改问题；新扩词只合并去重，不替换整个池。错误保留编辑输入。
10. 记录模型、处理状态、时间及可识别的input/output/total/cache tokens。供应商缺少或不一致usage时为null，不能说成零用量。响应结构验证之前先记录可用usage，格式失败也不抹掉已有用量。

当前实现是有持久化状态的同步短请求，支持完成结果取回和明确未知状态；不是已上线的常驻AI Worker或自动续跑队列。进程中断后不会自动发起第二次请求，也不承诺能取回供应商尚未返回的响应。Worker调度与正文生成属于后续步骤。

## 4. 任务快照与来源约束

接口：`GET/POST /api/workspace/[company]/geo/tasks`、`GET/PATCH /tasks/[id]`。

保存时服务端在事务中再次检查：优化词/素材组属于当前客户且版本一致、素材组未归档、每题属于该配置、实际可用图片数量足够。每篇允许1—10张；本批篇数至少1且不超过问题数。循环模式也只保存有限批次，不提供“不限制”。短篇1000以内、长篇2000以内；计数口径为中文字符、其余语言词数，正文实际计数及校验在第5步实现。

每次成功保存冻结：

- 优化词ID与版本、品牌、比对标识、核心词/10细分词、官网和Blog根地址。
- 问题ID、意图、原文/译文及当前目标语言。
- 素材组ID、版本、名称、有序可用媒体信息；每篇用图数量。
- 该配置版本已经核查可用的独立子页面、标题、摘录、匹配词和检查时间；缺来源的词及捕获时间。
- 方向、长度、模式和有限数量。

来源按钮复用第3步有域名/路径/robots/SSRF限制的真实发现服务，用户主动点击时才读取站点；没有逐词URL绑定表。检查完后需要保存任务，才能更新该任务的来源快照。本轮未点击此按钮抓取真实网站。

只把当前配置版本可用、仍在配置范围内的独立页面纳入快照。核心词问题至少需要一个关联细分词的来源页；细分词问题需要自己的匹配页。没有覆盖全部任务问题时仍可保存，但状态是**待补充来源**并列出缺失词，不能声称可进入真实正文生成。缓存中来源覆盖齐全时为**来源已配置**，仍不代表生成、发布或AI搜索命中。第5步还要复查来源、图片和事实，按实际可处理问题数校验生成数量。

新建请求UUID重复提交返回原任务，不增加修订；不同内容复用同一UUID拒绝。修改使用期望version，只允许一个并发修改成功。任务与修订在同一事务提交，失败全部回滚。以后更改优化词或素材组不会回写旧任务快照，也不会改变旧任务的修订。

页面提供显式读取已保存任务、刷新优化词/素材版本及采用新版本；读取任务会提示放弃未保存修改。失败不自动覆盖输入。未保存和处理中状态复用工作台离开/公司切换保护，页面卸载清理请求及旧客户状态。
