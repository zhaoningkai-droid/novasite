# 项目维护说明

本文适用于接手源码和维护版本流程的人。生产环境当前由阿里云 ECS 上的容器服务运行；这里不保存访问凭据、客户信息或真实服务器配置。

## 仓库维护

- 保持 `main` 可审阅；以短期功能分支开发，不在 `main` 上直接累积未完成改动。
- PR/合并应说明用户可见行为、涉及集合/API/迁移、回退影响和验证证据。
- 生产发布必须从已审阅的 Git commit 构建；保存 Web 和 Worker 各自的 commit、lockfile 摘要、镜像 registry digest 和发布记录。
- 标签不可移动。现有 `v1.0.0` 属于历史源代码快照，不要用来指向新基线。
- README 说明产品当前边界；历史计划保留原时间和适用范围。当前进度集中更新 `docs/PROJECT_STATUS.md`。

## 日常运行责任

生产值班人员应通过受控的阿里云运维入口核对 ECS 状态、容器健康、磁盘/内存余量、Web 与 Worker 版本、PostgreSQL 可用性、Caddy 证书/入口以及翻译队列积压。不要将控制台截图、SSH 输出、访问日志、客户域名/询盘或完整配置贴进公开 issue/PR。

数据库和媒体应有独立备份及可恢复检查。保留周期和 RPO/RTO 尚未在本资料里核实，因此不能承诺具体恢复时间。至少需记录备份时间、加密/访问控制、备份位置、恢复演练日期及责任人。

## 变更前检查

1. 确认工作区与分支；查看 `git status`，只选择本次授权文件，不要整体 stage 未审查文件。
2. 查看当前生产 Web/Worker 版本和数据库迁移状态，但遵守当次任务的“只读/禁止生产访问”边界。
3. 对权限、租户字段、媒体、翻译任务、询盘和迁移变更进行针对性审查。
4. 查阅 Next.js 版本匹配的本地文档和 `AGENTS.md`，再改源码。
5. 本地/CI 验证不得加载生产 `.env`、连接生产数据库或调用真实 AI provider。

## 公开提交前安全审查

扫描工作树与将要提交的 Git 历史，重点检查：`.env`、`.private`、密钥、SSH/TLS 文件、数据库 dump、客户媒体、网站日志、用户/询盘导出、带账号的截图、生产配置、个人绝对路径、云厂商/AI API token。逐个审查二进制文件与 seed/导入脚本；文本正则扫描不能替代人工代码审查。

发现已经公开的真实凭据时，不要仅删除当前文件或盲目重写公开历史；先立即轮换凭据并按安全事件流程处理，再由负责人决定是否需要清除历史对象和通知受影响人员。

## 许可和素材

项目自有代码采用 MIT；Payload 的上游来源保留在 `THIRD_PARTY_NOTICES.md`。依赖的许可证以锁文件对应的具体版本为准。演示图片逐项检查 source page、许可和用途记录；不得将演示图片复制成客户媒体，也不得暗示其是客户实绩。尚无来源页或授权无法确认的设计截图不进入当前候选工作树。

## 本次公开安全修订

当前候选的 seed 入口在生产环境直接拒绝执行；非生产环境也需要显式设置 `NOVASITE_ENABLE_SEED=true`。HTTP seed 路由和破坏性 seed 函数都校验 `super-admin`，独立数据脚本还要求指定已有平台管理员。演示作者使用运行时生成的随机密码，不存在固定演示账户口令。详见[安全修订记录](./RELEASES/security-revision-2026-10.md)。这些安全修订尚未部署到生产。

演示模板联系字段使用 `.invalid` 保留域名、虚构号码和演示地址。带旧企业品牌的产品资料已替换为明确标识的 NovaSite 样例 PDF。辅助测试/登录脚本不再带固定后台口令或硬编码 SSH 目标；需要的值须从本机环境读取。演示图片的来源记录和许可边界见 `THIRD_PARTY_NOTICES.md` 及各素材 manifest。

候选当前文件树已移除旧后台参考截图和临时环境文件。本次保留 Git 历史，因此旧提交中的截图、本地路径和历史演示账号说明仍可从历史对象查看；当前公开 main 早已包含这些历史对象。没有重写历史。若负责人要求清除历史对象，需另行决定并审查对公开仓库克隆及标签的影响。
